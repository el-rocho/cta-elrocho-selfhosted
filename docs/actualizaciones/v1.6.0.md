# Actualización del servidor a 1.6.0

Esta nota se aplica al actualizar `cta-elrocho-selfhosted` desde `1.5.6` o una versión anterior a `1.6.0`.

Consulta primero la [guía general de actualización](../../UPGRADING.md) y realiza una copia consistente del directorio `data`.

## Resumen

La versión 1.6.0 añade el contexto de medicación antihipertensiva por usuario y por medición, la confirmación de presión de pulso y nuevos avisos calculados dinámicamente. La migración SQLite es automática, aditiva e idempotente.

No hay que recrear la base ni volver a importar el historial.

## Cambios de estructura

Al arrancar por primera vez, el servidor añade:

- `settings.takes_antihypertensive_medication`, entero con valor inicial `0`.
- `readings.pulse_pressure_confirmed`, entero con valor inicial `0`.
- `readings.takes_antihypertensive_medication`, entero que conserva el contexto de cada toma.

Después completa las mediciones cuyo contexto todavía sea nulo con el valor configurado para su usuario o, si no existe, con `0`.

No se modifican:

- Sistólica y diastólica.
- Pulsaciones.
- Fecha y hora.
- Brazo y notas.
- Usuarios, credenciales, 2FA y sesiones.

## Acción necesaria después de actualizar

La configuración de medicación no existía en 1.5.x, por lo que los perfiles anteriores parten habitualmente de **No toma medicación**.

Cada usuario debe:

1. Abrir Configuración.
2. Comprobar **¿Toma medicación antihipertensiva?**
3. Si toma medicación, seleccionar **Sí toma medicación**.
4. Elegir **Recalcular** cuando las mediciones antiguas se realizaron bajo ese mismo contexto.

Debe utilizar **Conservar** si el cambio refleja una modificación real del tratamiento y quiere preservar el contexto histórico anterior.

Las mediciones antiguas quedan con `pulse_pressure_confirmed = 0`, porque no es posible saber retrospectivamente si el usuario revisó y confirmó el manguito.

## Datos almacenados y avisos

SQLite almacena los valores originales, el contexto de medicación y la confirmación de una presión de pulso anómala. Los colores, indicadores del valor causante y textos informativos se calculan al consultar las mediciones; no se guarda una copia fija de cada mensaje.

## Cliente Android y PWA

Actualiza el cliente `cta-elrocho-client-app` a 1.6.0 después de comprobar el servidor. El cliente no contiene SQLite, pero necesita las rutas y campos nuevos para representar correctamente el contexto y los avisos.

Mantener un cliente 1.6.0 conectado de forma permanente a un servidor 1.5.x no es una configuración compatible.

## Compatibilidad al volver atrás

La migración solo añade columnas y el servidor 1.5.6 debería ignorar los campos que no conoce. Aun así, la recuperación recomendada es restaurar la copia completa de `data` realizada antes de actualizar y arrancar la imagen anterior.

Si se registraron mediciones después de actualizar, no estarán en la copia previa. Conserva también la base posterior o exporta esas mediciones antes de restaurar.
