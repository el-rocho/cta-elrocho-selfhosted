# Actualización del servidor a v1.7.1

> [!IMPORTANT]
> Realiza una copia completa del directorio `data` con el contenedor detenido antes de actualizar, como en cualquier cambio de versión. Esta versión **no modifica la base de datos ni la API**: sólo cambia la interfaz web y la lista de orígenes admitidos por omisión.

## Resumen de cambios

- **Origen de la PWA oficial del cliente.** La lista de orígenes admitidos por omisión incluye ahora `https://cliente.cta.elrocho.es`, el dominio definitivo de la PWA del cliente. Si abrías esa PWA contra este servidor y veías un fallo de conexión con el servicio operativo, era este el motivo.
  - El origen antiguo (`https://el-rocho.github.io`) deja de admitirse: esa dirección redirige al dominio definitivo, así que el navegador nunca envía el origen antiguo.
  - Si defines `CORS_ORIGINS` a mano, añade `https://cliente.cta.elrocho.es` a tu lista: al declarar la variable sustituyes por completo la lista por omisión.
- **Interfaz web: toma de datos y pantalla inicial.** Misma renovación que en las otras dos variantes:
  - el formulario abre vacío y `115`, `65` y `60` son solo referencias visuales que no se guardan sin interacción;
  - la rueda consolida el valor más próximo una sola vez al detenerse, alinea el elemento central y admite teclado;
  - los borradores caducan a los 5 segundos y el formulario se bloquea mientras se guarda;
  - «Faltan datos» y «Revisa el manguito y repite la medición» pasan a diálogos superpuestos que no desplazan el formulario;
  - el botón principal se rotula **Registrar medición**;
  - el aviso de hipertensión grave pierde las instrucciones de urgencia y se presenta como `Hipertensión grave (200/120)`;
  - la zona informativa bajo la acción principal ocupa una sola línea flexible;
  - Evolución se inicia plegada, las guías se muestran como `USA AHA/ACC 2025` e `Int. ISH 2020` y la pantalla inicial queda más compacta;
  - la clasificación y los avisos solo se recalculan con una lectura completa y plausible.
- **Sin migraciones.** No hay comandos SQL que ejecutar al arrancar.

## Actualizar y comprobar

```bash
git pull --ff-only
sudo docker compose pull
sudo docker compose up -d
sudo docker logs --tail 100 control-tension-server
```

Comprueba el inicio de sesión, el historial, la configuración de un usuario existente y el panel de estado. Si sirves la PWA del cliente desde `https://cliente.cta.elrocho.es`, abre esa dirección y confirma que carga las mediciones sin error de conexión.

## Problemas más probables

- **Fallo de conexión con el servidor operativo** (la ruta `/api/health` responde): la página que ejecuta la aplicación se sirve desde un origen que no está declarado. Comprueba `CORS_ORIGINS` y, si defines la variable, incluye en ella `https://cliente.cta.elrocho.es`.
- **La PWA del cliente sigue sin conectar tras actualizar**: el servidor en ejecución no es el de esta versión. Revisa con `sudo docker compose ps` que la imagen corresponda a `1.7.1`.
- **`403` con «Token explícito requerido»**: la petición no traía la cabecera de sesión. Es lo que ve un cliente anterior a `1.7.0`; actualízalo.
