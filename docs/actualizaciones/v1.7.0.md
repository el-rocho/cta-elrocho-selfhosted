# Actualización del servidor a v1.7.0

> [!IMPORTANT]
> Esta versión **exige el token de sesión en toda su API de datos** y sólo entrega las respuestas a orígenes declarados. Actualiza también los clientes a `1.7.0`: un cliente `1.6.1` o anterior no envía el token en la mayoría de las peticiones y no podrá leer ni guardar datos contra este servidor. Realiza además una copia completa del directorio `data` antes de actualizar.

## Resumen de cambios

- **Nombres de copia saneados.** Las copias que el servidor guarda en `data/backups/` se componen con un prefijo validado y un nombre de usuario normalizado; ningún valor puede sacar el archivo de ese directorio. Sin contenido no se anuncia una copia ni se adelanta su fecha.
- **Token explícito en toda la API de datos.** Además de la sesión, cada petición debe traer la cabecera `X-Session-Token`. Sin ella el servidor responde `403` y no llega a tocar la base de datos. Sólo quedan fuera las rutas del flujo de acceso: comprobación de estado, alta inicial, inicio de sesión, verificación en dos pasos y cierre de sesión.
- **Orígenes restringidos (CORS).** Las peticiones de navegador desde otro origen se aceptan únicamente si están declaradas en `CORS_ORIGINS`. Ya vienen admitidos los puertos de desarrollo, los de la aplicación Android/PWA y el de la PWA publicada en GitHub Pages.
- **Limpieza interna.** Se elimina código sin uso en las tres ediciones; no cambia el comportamiento de la interfaz.

## Si actualizas desde 1.6.0 o anterior

La migración automática de preferencias de la versión `1.6.1` se ejecuta igualmente al arrancar: no hay que ejecutar ningún comando SQL. Consulta [la nota de 1.6.1](v1.6.1.md) si necesitas el detalle.

## Actualizar y comprobar

```bash
git pull --ff-only
sudo docker compose pull
sudo docker compose up -d
sudo docker logs --tail 100 control-tension-server
```

Comprueba el inicio de sesión, el historial, la configuración de un usuario existente y el panel de estado. Después actualiza el cliente Android o la PWA a `1.7.0` y confirma que carga mediciones y guarda una toma.

## Problemas más probables

- **`403` con «Token explícito requerido»**: la petición no traía el token. Es lo que verá un cliente anterior a `1.7.0`; actualízalo.
- **Fallo de conexión con el servidor operativo** (la ruta `/api/health` responde): la página que ejecuta la aplicación se sirve desde un origen que no está declarado. Añádelo a `CORS_ORIGINS` y reinicia el contenedor.
- **Sesión que pide volver a iniciarla**: el navegador conserva la cookie pero ha perdido el token guardado. Vuelve a iniciar sesión; los datos permanecen en el servidor.
